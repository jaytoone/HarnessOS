## 1. 시드 코호트 목표 재정의

### iter 5의 n=10이 왜 호로스코프인가

iter 5 MVP spec은 "6개 아웃컴 카테고리 × 시드 10명"을 언급했으나, iter 8 메타-리뷰가 정확히 지적한 문제:

**아웃컴 카테고리 6개**:
1. 시리즈A+ 창업가
2. 월 500만+ 프리랜서
3. 테크리드/CTO 전환
4. 독립 컨설턴트 (기업 고객 3+)
5. 크리에이터 (구독자/팔로워 기반 수익)
6. 사내 전문가 → 외부 인정 전환 (강연, 출판, 자문)

**n=10/카테고리의 통계적 문제**:
- 중앙값 궤적을 계산하려면 최소한 분포의 중심 경향을 신뢰할 수 있어야 한다
- n=10에서 중앙값의 95% 신뢰구간: 표본의 3번째~8번째 순위 (Binomial CI) → 분포의 25-75 백분위를 포함
- 이것은 "중앙값"이 아니라 "아무 값이나 가능하다"는 의미
- 발산점 3개를 계산할 때, 각 발산점의 위치가 +-2 표준편차 범위에서 요동 → 사용자에게 보여주는 갭이 노이즈
- **호로스코프 효과**: 충분히 모호한 갭은 누구에게나 맞아 보인다. "이 시점에서 포트폴리오가 없다"는 n=10 기반이면 코호트의 우연적 특성일 수 있음

**수치 시뮬레이션 근거**:
- 궤적 비교의 핵심 변수: 역할 전환 시점, 회사 단계 패턴, 외부 아웃풋 시작 시점
- 각 변수가 연속형이고 분산이 크다고 가정하면, 중앙값 안정화에 필요한 최소 n ≈ 20-30 (Wilcoxon signed-rank power analysis, effect size d=0.5, power=0.8)
- 카테고리 6개 × 최소 n=10이면 60명이지만, 이는 "존재 증명" 수준
- 신뢰할 수 있는 발산점 감지: 카테고리당 n=15-20 → 총 90-120명

### 최소 유효 시드 크기

**목표를 재정의**: "60명 모집"이 아니라 "발산점 신호 대 잡음 비율(SNR) > 2.0을 달성하는 최소 n"

| 시나리오 | 카테고리당 n | 총 시드 | 중앙값 CI 폭 | SNR 추정 | 판정 |
|---|---|---|---|---|---|
| iter 5 원안 | 10 | 60 | IQR 전체 | < 1.0 | 호로스코프 |
| 최소 유효 | 15 | 90 | IQR × 0.6 | ~1.5 | 경계선 |
| 목표 | 20 | 120 | IQR × 0.45 | ~2.2 | 신뢰 가능 |
| 이상적 | 30 | 180 | IQR × 0.35 | ~3.0 | 견고 |

**결정**: MVP는 **카테고리당 n=15, 총 90명**을 1차 목표로 설정. 단, 모집 과정에서 카테고리별 편차가 클 경우, 가장 많이 모인 3개 카테고리를 먼저 론칭하고 나머지는 "데이터 수집 중"으로 표시.

**2단계 전략**:
- Phase 1 (Week 1-3): 90명 모집 시도, 실제 확보 60명+ 목표
- Phase 2 (Week 4-6): Phase 1 데이터 기반으로 부족 카테고리 집중 모집
- 론칭 기준: 최소 4개 카테고리에서 각 n >= 12 확보

## 2. ICP 스크리닝 기준 (operationalized)

theory v2의 핵심 ICP 조건은 **정체성 이동성(identity portability)**이다. 고용 형태가 아닌, 전문 정체성이 기관과 독립적으로 이동할 수 있는지가 기준.

### 스크리닝 질문 5개 (Yes/No)

**SQ1. "현재 하시는 일의 결과물(코드, 글, 디자인, 프로젝트 등)이 본인 이름으로 외부에서 확인 가능합니까?"**
- Yes: GitHub 프로필, 블로그, 포트폴리오 사이트, 출판물, 발표 영상 등
- No: 회사 내부 시스템에만 존재, 팀 이름으로만 공개
- **측정**: 외부 가시적 아웃풋 존재 여부

**SQ2. "지금 회사/클라이언트를 떠나도 같은 분야에서 3개월 이내에 동등 이상의 기회를 확보할 자신이 있습니까?"**
- Yes: 이직/전환 자신감 높음 = 이동성 있음
- No: 현 고용주 의존도 높음
- **측정**: 주관적 이동성 자신감

**SQ3. "최근 12개월 내에 현 조직 외부에서 전문성을 인정받은 경험이 있습니까? (외부 강연, 기고, 자문, 헤드헌팅 연락, 커뮤니티 인정 등)"**
- Yes: 외부 시장에서 신호 발생
- No: 내부 평가만 존재
- **측정**: 외부 인정 이벤트 발생 여부

**SQ4. "본인의 전문 분야에서 '잘 되고 있는 동료'와 비교했을 때, 그 사람이 자신보다 무엇을 더 알고 있는지 구체적으로 떠오르는 것이 있습니까?"**
- Yes: 갭 인식 활성화 상태 (L4+ 신호)
- No: 비교 대상 부재 또는 갭 인식 없음
- **측정**: unknown-unknown 갭 사전 인식

**SQ5. "지금 하시는 일을 2년 더 같은 방식으로 하면 정체될 것 같다는 불안이 있습니까?"**
- Yes: 변화 긴급성 존재
- No: 현 상태 만족
- **측정**: 변화 긴급성 (L4-L5 전제 조건)

### 통과 기준

- **3/5 이상 Yes → 모집 대상** (ICP 적합)
- **2/5 Yes → 조건부 포함** (인터뷰 후 판단)
- **1/5 이하 → 제외** (현재 ICP 미달)

### 카테고리 배정 기준

스크리닝 통과 후, 아웃컴 카테고리 배정:
- 자가 신고 아웃컴 + 검증 질문 1개로 배정
- "현재 어떤 상태이십니까?" → 6개 카테고리 중 매칭
- "목표로 하는 아웃컴은?" → 사용자 궤적 비교 대상 결정

## 3. 모집 채널 x 메시지 매트릭스

### 전략 원칙

- 모집 메시지는 **제품 소개가 아닌 갭 진단 프레임**으로 작성
- "이런 제품 만들고 있어요"가 아닌 "이런 질문에 대한 답을 찾고 있어요"
- 대상자가 **자신의 이야기를 하고 싶어지는** 프레이밍

### 채널별 전략

| 채널 | ICP 매칭도 | 예상 전환율 | 필요 노출 | 메시지 핵심 |
|---|---|---|---|---|
| LinkedIn 콜드 DM | 85% | 8-12% | 750-1,125명 | 커리어 궤적 연구 참여 요청 |
| Disquiet 커뮤니티 | 90% | 15-20% | 450-600명 | 창업가/프리랜서 궤적 패턴 공유 |
| 카카오 오픈채팅 (직군별) | 70% | 5-8% | 1,125-1,800명 | 같은 직군 성장 경로 비교 |
| 커뮤니티 커피챗 (오프라인) | 95% | 25-35% | 257-360명 | 직접 대화 → 온라인 전환 |
| Twitter/X 콜드 DM | 80% | 6-10% | 900-1,500명 | 외부 아웃풋 보유자 타겟 |
| 글또/AWSKRUG 등 기술 커뮤니티 | 85% | 12-18% | 500-750명 | 기술 커리어 궤적 데이터 연구 |
| 프리랜서 플랫폼 (크몽/숨고 상위) | 75% | 4-7% | 1,286-2,250명 | 프리랜서 성장 궤적 분석 |

### 채널별 구체적 모집 메시지

**CH1. LinkedIn 콜드 DM**

> "안녕하세요. 커리어 궤적 패턴 연구 중인데, [상대방 직군]에서 [현재 포지션]까지 오신 경로가 흥미로워서요. 15분 인터뷰 가능하실까요? 결과 공유 드립니다."

- 타겟: 프로필에 이직 2회+, 외부 활동 기재자
- 발송 도구: LinkedIn 기본 메시지 (Sales Navigator 불필요, 1촌 아닌 경우 InMail)
- 일일 발송 한도: 20-30건 (계정 제한 방지)

**CH2. Disquiet 커뮤니티 게시글**

> "창업가/프리랜서 60명의 커리어 궤적을 분석해서 '성공 코호트와의 발산점'을 찾는 프로젝트 진행 중입니다. 참여하시면 본인 궤적 분석 리포트를 무료로 드려요. 5분 설문 링크:"

- 게시 위치: Disquiet 프로덕트 빌더 채널, 사이드 프로젝트 채널
- 후속: 댓글 참여자 개별 DM으로 스크리닝

**CH3. 카카오 오픈채팅 (직군별)**

> "개발자/디자이너/PM 커리어 성장 연구 참여자 모집합니다. 같은 직군 상위 20% 궤적과 내 궤적의 차이점을 분석해 드려요. 익명 보장, 소요 5분."

- 타겟 방: 개발자 커리어, PM 커뮤니티, 디자이너 성장, 프리랜서 모임
- 주의: 방 규칙 확인 후 게시, 관리자 사전 허가 권장

**CH4. 커뮤니티 커피챗 (오프라인)**

> "[행사명] 참석하신 분들 중 커리어 궤적 비교 연구에 관심 있으신 분 계실까요? 비슷한 배경에서 출발해서 다른 결과에 도달한 패턴을 찾고 있어요. 커피 한 잔 사드릴게요."

- 장소: 스타트업 밋업 (MASH-UP, DDD, Nexters 등), 프리랜서 모임
- 방식: 행사 후 관심자 5-8명 그룹 대화 → 개별 인터뷰 전환
- 장점: 가장 높은 전환율, ICP 직접 확인 가능

**CH5. Twitter/X 콜드 DM**

> "트윗에서 [구체적 주제] 관련 글 인상적이었어요. 비슷한 배경의 전문가 궤적 비교 연구 중인데, 15분 대화 가능하실까요? 분석 결과 공유 드립니다."

- 타겟: 기술 블로그 운영자, 오픈소스 기여자, 프리랜서 공개 활동자
- 전제: 상대방의 구체적 아웃풋을 언급해야 응답률 상승

**CH6. 글또/AWSKRUG 등 기술 커뮤니티**

> "기술 직군 커리어 궤적 데이터 분석 프로젝트에 참여자를 찾고 있습니다. 같은 연차/직군에서 목표 달성 속도가 다른 이유를 궤적 데이터로 분석합니다. 참여 시 본인 궤적 리포트 제공."

- 게시 위치: 글또 슬랙, AWSKRUG 디스코드, 인프런 커뮤니티
- 형식: 짧은 소개 + 구글폼 링크 (스크리닝 질문 포함)

**CH7. 프리랜서 플랫폼 (크몽/숨고 상위)**

> "프리랜서 성장 궤적 연구 참여 요청드립니다. 월 수익 상위 프리랜서의 커리어 패턴을 분석 중이에요. 5분 설문 + 선택적 15분 인터뷰. 분석 리포트 무료 제공."

- 타겟: 크몽 프라임/숨고 TOP 등급 프리랜서
- 접근: 플랫폼 내 메시지 또는 외부 연락처 확보 후 접촉

### 채널 우선순위 (Phase 1 집중)

1. **LinkedIn 콜드 DM** — 가장 넓은 ICP 풀, 프로필 기반 사전 스크리닝 가능
2. **Disquiet** — 창업가/빌더 집중, 높은 전환율
3. **커뮤니티 커피챗** — 가장 높은 품질, 소수 확보에 적합
4. 나머지 채널은 Phase 1 결과 보고 Phase 2에서 활성화

## 4. 첫 접촉 스크립트 (콜드 DM 버전)

### 공통 원칙 (iter 10 프로토콜 연결)

- **판매 프레임 금지**: "제품", "서비스", "가격" 언급 없음
- **갭 진단 프레임**: "연구 참여" → "궤적 비교" → "발산점 발견" → 자연스러운 호기심 유발
- **상호성 장치**: 참여 대가로 "본인 궤적 분석 리포트" 제공
- **탈출구 명시**: 부담 없이 거절할 수 있는 표현 포함
- iter 10 인터뷰 프로토콜의 Q1-Q6은 인터뷰 본문에서 사용, DM에서는 호기심만 유발

### 버전 A: 창업가용

```
[이름]님 안녕하세요.

커리어 궤적 패턴 연구를 하고 있는 [본인 이름]입니다.

시리즈A 이상 도달한 창업가분들의 창업 전 커리어 궤적을 모으고 있는데,
[상대방 회사/프로덕트] 이전 경력이 흥미로워서 연락드렸어요.

같은 배경에서 출발한 사람 중 시리즈A에 빠르게 도달한 그룹과
그렇지 못한 그룹의 궤적 차이를 분석하고 있습니다.

15분 정도 간단한 대화 가능하시면,
분석 결과 나오면 [이름]님 궤적 리포트도 공유드리겠습니다.

혹시 시간 괜찮으신 타이밍이 있으실까요?
부담 없이 패스하셔도 됩니다.
```

**핵심 메커니즘**:
- "같은 배경에서 출발한 사람 중 차이" → Social Amplifier 활성화 (Q3 사전 프라이밍)
- "궤적 차이를 분석" → unknown-unknown 호기심 유발
- "리포트 공유" → 상호성, 참여 인센티브

### 버전 B: 프리랜서용

```
[이름]님 안녕하세요.

프리랜서 커리어 궤적 연구를 진행 중인 [본인 이름]입니다.

월 수익 기준 상위 프리랜서분들이 독립 전후로 어떤 궤적을 밟았는지
패턴을 찾고 있어요. [상대방의 구체적 아웃풋/활동] 보고 연락드렸습니다.

비슷한 스킬셋으로 시작한 프리랜서 중에서
수익과 인지도 면에서 빠르게 성장한 그룹의 공통 패턴이 있는지,
반대로 정체되는 지점이 어딘지를 데이터로 확인하려고 합니다.

5분짜리 온라인 설문 + 선택적으로 15분 대화까지 가능하시면 좋고,
결과 나오면 [이름]님 궤적 분석 리포트를 보내드릴게요.

관심 있으시면 편하게 답 주세요. 아니어도 괜찮습니다.
```

**핵심 메커니즘**:
- "수익과 인지도 면에서 빠르게 성장한 그룹" → 비교 욕구 활성화
- "정체되는 지점이 어딘지" → 미래 공포 가볍게 자극 (Q5 사전 프라이밍)
- "데이터로 확인" → 과학적 프레임으로 판매 방어벽 해제


- "회사 안에서만 성장 vs 외부 인지도까지" → Q8의 "내 이름으로 쌓고 있다" 프라이밍
- "외부 활동을 하시는 분들의 관점이 특히 중요" → 선택된 느낌, 응답 동기 상승

## 5. 온보딩 5필드 → 궤적 데이터 수집 설계

### iter 5 MVP의 5-field onboarding 구체화

MVP의 핵심 원칙: **3분 이내 완료, 로그인 불필요, 궤적 형태만 수집 (세부 이력 아님)**

---

### 필드 1: 역할 시퀀스

**질문 텍스트**:
> "지금까지의 주요 직업/역할을 시간 순서대로 적어주세요. (최소 2개, 최대 5개)
> 예: 백엔드 개발자 → 테크리드 → CTO"

**데이터 타입**: Array<String>, length 2-5
**검증 조건**:
- 최소 2개 역할 필수
- 각 역할은 2-30자 텍스트
- 빈 문자열 불허
- 순서가 시간순인지 확인 불가 → UI에서 드래그 재정렬 제공

**응답 품질 게이트**:
- FAIL: 역할이 1개뿐 → "현재 역할만으로는 궤적 비교가 어렵습니다"
- WARN: 역할이 모두 동일 직급 (예: "개발자 → 개발자 → 개발자") → 회사/맥락 변화 추가 요청
- PASS: 2개 이상, 역할 변화 또는 맥락 변화 존재

---

### 필드 2: 각 역할의 조직 단계

**질문 텍스트**:
> "각 역할을 수행한 조직의 단계를 선택해주세요.
> 1인/프리랜서 | 초기 스타트업(~10명) | 성장 스타트업(10-100명) | 중견(100-1000명) | 대기업(1000명+)"

**데이터 타입**: Array<Enum>, 필드 1과 동일 length
**Enum 값**: `solo` | `early_startup` | `growth_startup` | `mid` | `enterprise`
**검증 조건**:
- 필드 1의 역할 수와 정확히 매칭
- 각 항목 필수 선택 (null 불허)

**응답 품질 게이트**:
- FAIL: 전부 동일 단계 + 역할도 동일 → 궤적 변화 부재, 비교 무의미
- WARN: 필드 1과 논리적 불일치 (예: "CTO" + "대기업 1000명+" → 가능하지만 드묾, 확인 팝업)
- PASS: 최소 1회 단계 변화 존재

---

### 필드 3: 외부 아웃풋 유형

**질문 텍스트**:
> "본인 이름으로 외부에 공개된 결과물이 있으면 모두 선택해주세요. (복수 선택)
> 블로그/글 | GitHub/코드 | 발표/강연 | 포트폴리오 | 출판물 | 없음"

**데이터 타입**: Array<Enum>, multi-select
**Enum 값**: `blog` | `github` | `talk` | `portfolio` | `publication` | `none`
**검증 조건**:
- `none` 선택 시 다른 항목과 동시 선택 불가
- 최소 1개 선택 필수

**응답 품질 게이트**:
- INFO: `none` 선택 → 정체성 이동성 낮음 신호, 하지만 데이터 수집은 유효
- WARN: 없음 → 이 사용자의 발산점에서 "외부 아웃풋" 항목이 과대 가중될 수 있음 → 발산점 계산 시 가중치 조정 플래그
- PASS: 1개 이상 아웃풋 유형 선택

---

### 필드 4: 목표 아웃컴

**질문 텍스트**:
> "12-24개월 내에 도달하고 싶은 상태를 하나 선택해주세요.
> 1. 시리즈A 이상 투자 유치
> 2. 프리랜서 월 순수익 500만원+
> 3. 테크리드/CTO 포지션 전환
> 4. 독립 컨설턴트 (기업 고객 3곳+)
> 5. 크리에이터 (구독/팔로워 기반 수익)
> 6. 사내 전문가에서 외부 인정 전환 (강연, 출판, 자문)"

**데이터 타입**: Enum, single-select
**Enum 값**: `series_a` | `freelance_500` | `tech_lead` | `consultant` | `creator` | `external_recognition`
**검증 조건**:
- 정확히 1개 선택 필수
- null 불허

**응답 품질 게이트**:
- PASS: 모든 선택이 유효
- 특이사항: 이 필드가 사용자를 비교 코호트에 배정하는 핵심 키 → 잘못된 선택 시 전체 발산점이 무의미해짐
- **호로스코프 원인 #1**: 사용자가 실제 목표와 다른 것을 선택 (예: 실제로는 프리랜서를 원하는데 "CTO"를 선택) → UI에서 선택 후 확인 문구: "정말 이 목표가 12-24개월 내 가장 중요한 목표입니까?"

---

### 필드 5: 현재까지의 경력 기간

**질문 텍스트**:
> "첫 직업/역할을 시작한 시점부터 지금까지 몇 년째입니까?
> 1-2년 | 3-5년 | 6-10년 | 11-15년 | 16년+"

**데이터 타입**: Enum, single-select
**Enum 값**: `1_2y` | `3_5y` | `6_10y` | `11_15y` | `16y_plus`
**검증 조건**:
- 정확히 1개 선택 필수
- null 불허

**응답 품질 게이트**:
- WARN: `1_2y` + 목표 아웃컴 `series_a` 또는 `consultant` → 비교 코호트 매칭이 어려울 수 있음 (경고 표시, 수집은 진행)
- PASS: 모든 조합 유효

---

### 종합 응답 품질 판정

| 조건 | 판정 | 조치 |
|---|---|---|
| 5필드 모두 PASS | 유효 데이터 | 궤적 계산 진행 |
| 1개 이상 WARN | 조건부 유효 | 데이터 수집 + 계산 시 가중치 조정 |
| 1개 이상 FAIL | 무효 데이터 | 재입력 요청, 재입력 불가 시 제외 |
| 완료 시간 30초 미만 | 의심 데이터 | 자동 플래그, 수동 검토 |
| 완료 시간 10분 초과 | 이탈 위험 | 중간 저장 + 리마인더 |

### "호로스코프 원인"이 되는 응답 패턴

수집 데이터가 발산점 계산을 왜곡하는 주요 패턴:

1. **목표 아웃컴 불일치**: 실제 욕구와 다른 카테고리 선택 → 코호트 미스매칭 → 발산점이 무관한 차원에서 발생
2. **역할 시퀀스 과도 단순화**: "개발자 → 개발자" (실제로는 백엔드→풀스택→아키텍트이나 "개발자"로 통일) → 궤적 변화 감지 불가
3. **조직 단계 오분류**: 100명 스타트업을 "대기업"으로 분류 → 코호트 궤적과 비교 축 왜곡
4. **외부 아웃풋 과소 신고**: 존재하는데 "없음" 선택 → 발산점에서 "아웃풋 부재"가 거짓 양성으로 출현
5. **경력 기간 라운딩**: 5.5년을 "3-5년"으로 → 코호트 내 궤적 속도 계산 왜곡

**대응**: 필드 1-2에 대해 자유 텍스트 보조 필드 추가 (선택사항), 이상치 자동 플래그, 시드 코호트에서는 인터뷰로 교차 검증.

## 6. 시드 코호트 → 유효 코호트 전환 기준

### "아웃컴 확인됨" 분류 조건

시드 코호트는 **이미 목표 아웃컴에 도달한 사람**이다. 이들의 궤적이 비교 기준선이 되므로, 아웃컴이 실제로 확인되어야 한다.

**카테고리별 확인 기준**:

| 카테고리 | 확인 방법 | 최소 증거 |
|---|---|---|
| 시리즈A+ 창업가 | 투자 뉴스, 크런치베이스, 본인 확인 | 투자 공시 또는 투자사 확인 가능 |
| 월 500만+ 프리랜서 | 자가 신고 + 플랫폼 등급 교차 검증 | 최근 3개월 평균 기준 |
| 테크리드/CTO | LinkedIn/채용 공고 교차 검증 | 현재 직함 + 팀 규모 확인 |
| 독립 컨설턴트 | 자가 신고 + 클라이언트 수 | 최근 12개월 기업 고객 3곳+ |
| 크리에이터 | 공개 프로필 팔로워/구독자 수 | 수익화 증거 (유료 구독, 광고 등) |
| 외부 인정 전환 | 강연/출판/자문 이력 확인 | 최근 12개월 외부 활동 3건+ |

### 유효 코호트 전환 기준

수집된 시드 데이터가 발산점 계산에 사용되려면:

**필수 조건 (모두 충족)**:
1. 아웃컴 확인 완료 (위 표 기준)
2. 온보딩 5필드 전부 PASS 또는 WARN (FAIL 없음)
3. 역할 시퀀스 최소 3개 (2개는 궤적 변화 감지 부족)
4. 최소 1회 조직 단계 변화 존재

**선택 조건 (충족 시 데이터 품질 상승)**:
- 인터뷰 완료 (iter 10 프로토콜) → 데이터 교차 검증됨
- 외부 아웃풋 1개 이상 존재 → 정체성 이동성 확인

### 반증 위험 알림: MVP 가설 재검토 트리거

다음 패턴이 관찰되면 MVP 가설 자체를 재검토해야 한다:

**트리거 1: 발산점 동질성** (위험도: 높음)
- 6개 카테고리 모두에서 동일한 발산점 3개가 반복 출현
- 의미: 궤적 비교가 아닌 일반적 조언 생성기가 되고 있음
- 조치: 아웃컴 카테고리 분류 재검토, 발산점 계산 알고리즘 점검

**트리거 2: 사용자 반응 무차별** (위험도: 높음)
- 발산점 공개 후 "맞아요!" 반응률이 카테고리 무관하게 80%+ 
- 의미: 바넘 효과 — 발산점이 충분히 모호해서 누구에게나 적용
- 조치: 발산점 구체성 측정 (발산점 텍스트에 사용자 고유 데이터 포함 비율 확인)

**트리거 3: 코호트 크기 불균형** (위험도: 중간)
- 특정 카테고리에 n < 8, 다른 카테고리에 n > 30
- 의미: 소수 카테고리의 "중앙값"이 사실상 개별 사례
- 조치: 소수 카테고리 일시 비활성화, 해당 카테고리 모집 집중

**트리거 4: 갭 닫기 불가능 판정** (위험도: 중간)
- 발산점 3개 중 2개 이상이 "과거 시점의 결정"에 해당 (예: "5년 전에 스타트업을 선택했어야")
- 의미: 갭이 닫을 수 있는 것이 아니라 후회를 보여주는 것 → Attainability 붕괴
- 조치: 발산점 필터에 "현재 시점에서 조치 가능한 갭만 표시" 규칙 추가

**트리거 5: 유료 전환 0%** (위험도: 치명적)
- 발산점 공개까지는 도달하지만 블러 해제(유료)로 전환 없음
- 의미: 갭 공개가 판매 순간이 아님 — theory v2의 핵심 명제 반증
- 조치: 인터뷰 10건 긴급 실시 (왜 안 샀는지), 가격/프레이밍/갭 품질 중 원인 분리

**트리거 6: 시드 코호트 궤적 분산 과대** (위험도: 중간)
- 같은 카테고리 내에서 궤적 패턴이 너무 다양해 "중앙값 궤적" 자체가 무의미
- 의미: 6개 카테고리가 충분히 세분화되지 않음
- 조치: 카테고리 세분화 (예: "시리즈A 창업가" → "기술 창업가" / "비기술 창업가")

## 7. 6주 실행 타임라인

### Week 1: 인프라 + 1차 모집 시작

**Day 6-7: 초기 응답 분석**
- 응답률 측정 (채널별)
- 스크리닝 통과율 확인
- 메시지 A/B 테스트 결과 초기 확인

**Week 1 목표**: 스크리닝 완료 15명+, 인터뷰 예약 5건+

---

### Week 2: 모집 확대 + 1차 인터뷰

**Day 8-10: 모집 확대**
- LinkedIn DM 지속 (누적 200건)
- 카카오 오픈채팅 3-5개 방 게시
- 글또/AWSKRUG 슬랙 게시

**Day 11-14: 1차 인터뷰 시작**
- iter 10 프로토콜로 인터뷰 진행 (주 5-8건)
- 인터뷰 후 온보딩 5필드 수집
- 아웃컴 확인 작업 시작

**Week 2 목표**: 스크리닝 완료 35명+, 인터뷰 완료 10건+, 아웃컴 확인 8명+

---

### Week 3: 집중 모집 + 데이터 품질 1차 점검

**Day 15-17: 부족 카테고리 집중**
- Week 1-2 데이터 기반 카테고리별 현황 확인
- 부족 카테고리 타겟 모집 (채널 + 메시지 조정)
- 커뮤니티 커피챗 1-2회 참석

**Day 18-21: 데이터 품질 점검**
- 수집된 5필드 데이터 품질 감사
- "호로스코프 원인" 패턴 존재 여부 확인
- 필요 시 재입력 요청 또는 보조 질문 추가

**Week 3 목표**: 스크리닝 완료 55명+, 유효 코호트 확정 30명+

**Week 3 게이트**: 유효 코호트 30명 미만 시 → Week 4를 모집 연장으로 전환

---

### Week 4: 인터뷰 집중 + 궤적 데이터 정제

**Day 22-25: 인터뷰 집중 주간**
- 주 8-10건 인터뷰 (iter 10 프로토콜)
- 인터뷰 데이터와 5필드 데이터 교차 검증
- 아웃컴 확인 완료 (외부 증거 수집)

**Day 26-28: 데이터 정제**
- FAIL/WARN 데이터 재수집 또는 제외 판정
- 카테고리별 n 확인 → 부족 카테고리 추가 모집 결정
- 궤적 데이터 구조화 (발산점 계산 입력 형식으로 정리)

**Week 4 목표**: 유효 코호트 50명+, 4개 카테고리 이상 n >= 10

---

### Week 5: 1차 패턴 분석 + 반증 트리거 확인

**Day 29-31: 1차 발산점 계산**
- 카테고리별 중앙값 궤적 계산 (수동, 스프레드시트 기반)
- 발산점 후보 도출 (각 카테고리 상위 3개)
- 발산점 구체성 확인 — 바넘 효과 테스트

**Day 32-35: 반증 트리거 점검**
- 트리거 1 (발산점 동질성) 확인
- 트리거 6 (궤적 분산 과대) 확인
- 필요 시 카테고리 재분류

**Week 5 목표**: 최소 3개 카테고리에서 발산점 3개 도출, 반증 트리거 미발동

**Week 5 게이트**: 반증 트리거 1 또는 6 발동 시 → MVP 가설 재검토 워크숍 (1일)

---

### Week 6: 프로토타입 테스트 + 유료 전환 시그널 확인

**Day 36-38: 발산점 프로토타입**
- 5명 대상 발산점 결과를 수동으로 전달 (구글 슬라이드 또는 Figma 목업)
- 반응 관찰: "이거 맞아요" vs "이건 아닌데" vs "이런 게 있었어?"
- 바넘 효과 직접 테스트: 의도적으로 다른 카테고리의 발산점을 보여주고 반응 비교

**Day 39-40: 유료 전환 시그널 테스트**
- "이 갭이 왜 생겼는지, 닫는 데 걸리는 기간을 알고 싶으시면?" 질문
- 반응 3가지 분류: 즉시 관심 / 조건부 관심 / 무관심
- 가격 감수성 확인: "월 29,000원이면?" 직접 질문

**Day 41-42: 종합 판정**
- 6주 데이터 종합 분석
- Go/No-Go 판정 기준:
  - GO: 유효 코호트 60명+, 반증 트리거 미발동, 프로토타입 긍정 반응 60%+, 유료 관심 30%+
  - PIVOT: 유효 코호트 40-59명, 또는 반증 트리거 1개 발동 → 카테고리 축소 후 재시도
  - KILL: 유효 코호트 40명 미만, 또는 반증 트리거 2개+ 발동, 또는 유료 관심 10% 미만

**Week 6 목표**: Go/Pivot/Kill 판정 완료, 다음 단계 결정
