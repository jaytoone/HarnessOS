## 1. 빠짐 정의 재정립

### 1A. 빠짐은 도덕 판단이 아니라 구조적 속성이다

"빠짐"이라는 단어는 한국어 맥락에서 부정적 뉘앙스를 갖지만, 본 프레임워크에서 빠짐은 **제품-사용자 관계의 구조적 패턴**을 지칭한다. 도덕적 비난이 아니라 공학적 진단이다.

**조작적 정의**: 제품 사용 N 사이클 후, 사용자가 제품 없이 동일 목표를 달성할 수 있는 능력이 **증가하지 않거나 감소**하는 상태.

수학적 표현:

```
Autonomy(t) = 사용자가 제품 없이 목표를 달성할 확률

건강한 제품: dAutonomy/dt > 0  (시간이 갈수록 자율성 증가)
빠짐 제품:   dAutonomy/dt <= 0 (시간이 갈수록 자율성 정체 또는 감소)
```

### 1B. 빠짐의 4가지 구성 조건

네 조건이 동시에 충족될 때 빠짐으로 진단한다. 하나만 충족되면 빠짐이 아닐 수 있다.

**조건 1 -- 갭 재생산 (Gap Reproduction)**
제품이 해소하는 갭과 동일하거나 유사한 갭을 제품 사용 자체가 재생성한다. 사용자는 "해결했다"고 느끼지만 실질적 갭은 줄지 않았다.

- 예: 매주 새 콘텐츠를 소비하지만, 소비 전과 후의 실행 능력 차이가 없음
- 반례: 갭이 재생성되더라도 사용자의 베이스라인 역량이 올라갔으면 빠짐 아님

**조건 2 -- 대안 차단 (Alternative Blocking)**
제품이 사용자의 독립적 문제 해결 경로를 의도적으로 차단하거나 보이지 않게 한다.

- 예: 제품 밖에서 동일 정보를 얻는 방법을 알려주지 않음
- 반례: 독점 데이터가 있어서 자연스럽게 대안이 없는 경우는 조건 2 미충족

**조건 3 -- 인출 비용 증가 (Escalating Exit Cost)**
사용 기간이 늘수록 떠나는 비용이 비례 이상으로 증가한다. 데이터 lock-in, 습관 형성, 정체성 매몰(sunk identity)이 작동한다.

- 예: 사용자 데이터를 내보낼 수 없는 구조, 스트릭/레벨 시스템
- 반례: 전환 비용이 존재하더라도 실질적 역량 축적이 있으면 건강한 lock-in

**조건 4 -- 자율성 인식 왜곡 (Autonomy Perception Distortion)**
사용자가 자신이 더 유능해졌다고 믿지만, 제품 없이 테스트하면 실제 능력이 향상되지 않았다.

- 예: 영어 학습 앱에서 앱 내 점수는 오르지만 실제 회화 능력은 정체
- 반례: 사용자가 자신의 의존을 자각하고 있으면 조건 4 미충족

### 1C. 건강한 리텐션 vs 의존성 리텐션 구분

둘 다 사용자가 계속 돌아오는 현상이지만 구조가 다르다.

| 차원 | 건강한 리텐션 | 의존성 리텐션 |
|---|---|---|
| 재방문 동기 | 새로운 프론티어 발견 | 미해소된 동일 갭 |
| 이탈 시 감정 | "졸업"의 성취감 | 불안, 상실감, 두려움 |
| 사용 중단 후 능력 | 유지 또는 향상 | 퇴행 |
| 추천 이유 | "여기서 X를 배웠다" | "없으면 안 된다" |
| 갭 방향 | 새 갭 > 기존 갭 (프론티어 이동) | 기존 갭 재순환 |

## 2. 건강도 진단 체크리스트 (Ethical_Coefficient 대리 지표)

### 2A. 갭 방향성 지표 (5개)

각 항목은 YES/NO로 답변한다. YES = 건강, NO = 위험 신호.

**GA-1. 코호트 갭 축소 측정**
> 동일 코호트의 사용자가 6개월 사용 후, 온보딩 시점에 측정한 핵심 갭 점수가 감소했는가?

측정법: 온보딩 시 자가 진단 → 6개월 후 동일 진단 재실시 → 점수 비교
- YES: 갭이 실제로 닫히고 있음
- NO: 갭 재생산 조건 1 의심

**GA-2. 이탈자 성공률**
> 제품을 떠난 사용자 중 목표를 달성한 비율이 비이탈 사용자와 유의미하게 다르지 않은가?

측정법: 이탈 후 3개월 서베이 (목표 달성 자가 보고)
- YES: 제품이 역량을 이전했음 (건강한 졸업)
- NO: 제품이 자체가 병목

**GA-3. 재구매 동기 변화**
> 갱신/재구매 시 사용자가 말하는 이유가 "새로운 것을 배우고 싶다"인가, "계속 써야 할 것 같다"인가?

측정법: 갱신 시점 1-질문 서베이 ("왜 갱신하셨나요?" 오픈)
- YES: "새 프론티어" 동기가 과반
- NO: "불안/습관" 동기가 과반 → 의존성 신호

**GA-4. 닫힌 갭 재활용 여부**
> 제품이 사용자가 이미 닫은 갭을 다시 표시하거나 콘텐츠를 반복 제공하는가?

측정법: 사용자별 닫힌 갭 목록 vs 제품이 표시하는 갭 목록 교차 확인
- YES (재활용 없음): 건강
- NO (재활용 있음): 인위적 갭 재생산

**GA-5. 상향 이동 비율**
> 유료 사용자 중 6개월 내 상위 티어 아웃컴으로 목표를 재설정한 비율이 20% 이상인가?

측정법: 목표 아웃컴 변경 이벤트 추적
- YES: 프론티어 확장이 작동 (사용자가 성장해서 새 목표가 생김)
- NO: 동일 목표에 갇혀 있음

### 2B. 사용자 자율성 지표 (5개)

Fogg의 B=MAP 모델과 Noggle(1996) 자율성 보존 기준을 적용한다.

**AU-1. 독립 실행 테스트 (핵심 지표)**
> 사용자에게 "제품 없이 지난 달 제품이 도와준 것과 같은 종류의 작업을 해보세요"라고 요청했을 때, 60% 이상이 "할 수 있다"고 답하는가?

측정법: 분기별 "독립 실행 자신감" 서베이 (1-5 리커트)
- YES (평균 3.5 이상): 역량 이전 성공
- NO (평균 3.5 미만): 제품 의존 형성

**AU-2. 숙고 시간 보존**
> 제품이 사용자에게 의사결정까지 최소 24시간의 숙고 시간을 기본 제공하는가?

측정법: 유료 전환, 업그레이드, 추가 구매 CTA에서 즉시 결제 vs 대기 옵션 확인
- YES: 자율성 보존 (Noggle 기준 충족)
- NO: 충동 구매 유도 → 조작 위험

**AU-3. 정보 투명성**
> 제품이 사용자에게 "이 제품이 작동하는 원리"를 설명하고, 제품 밖에서 동일 결과를 얻는 방법을 안내하는가?

측정법: 도움말/FAQ에 "제품 없이 이 작업을 하는 법" 섹션 존재 여부
- YES: 대안 차단 없음
- NO: 조건 2 (대안 차단) 충족

**AU-4. 데이터 이동성**
> 사용자가 자신의 데이터를 표준 포맷(CSV, JSON 등)으로 완전히 내보낼 수 있는가?

측정법: 내보내기 기능 존재 여부 + 내보낸 데이터의 완전성 확인
- YES: 인출 비용 제한적
- NO: 조건 3 (인출 비용 증가) 충족

**AU-5. 습관 vs 의도 비율**
> 사용자의 일일 접속 중 "의도적 목표를 가지고 접속"한 비율이 50% 이상인가?

측정법: 접속 시 "오늘 뭘 하러 왔나요?" 1-탭 분류 (습관적 확인 / 특정 목표)
- YES: 의도적 사용이 지배
- NO: 습관 루프 형성 → 자율성 저하 신호

### 2C. 사회적 증폭 지표 (3개)

Social_Amplifier가 사용자의 정체성을 **증폭**하는지 **대체**하는지 구분한다.

**SA-1. 제품 외 정체성 표현**
> 사용자가 제품을 언급하지 않고 자신의 전문성을 설명할 수 있는가?

측정법: 사용자 인터뷰에서 "본인 소개를 해주세요" → 제품명 미등장 비율
- YES (70% 이상 제품명 미등장): 정체성 증폭 (건강)
- NO (다수가 제품명으로 자기를 소개): 정체성 대체 (위험)

**SA-2. 사회적 비교 방향**
> 제품이 "당신은 뒤처져 있다"(하향 비교 유도)보다 "여기서 갈 수 있다"(상향 목표 제시) 메시지를 더 많이 사용하는가?

측정법: 알림/이메일/인앱 메시지 텍스트 분류 (하향 비교 vs 상향 목표)
- YES (상향 > 하향): 건강한 동기 부여
- NO (하향 >= 상향): FOMO 착취 → 수치심 기반 리텐션

**SA-3. 커뮤니티 졸업 축하**
> 제품이 사용자의 "졸업"(목표 달성 후 이탈)을 긍정적으로 다루는가?

측정법: 졸업/이탈 프로세스에서의 UX 톤 분석 + 졸업 사례 공유 여부
- YES: 건강한 수명 주기 인정
- NO: 떠나는 것을 실패로 프레이밍 → 의존 유지

## 3. 빠짐 위험 점수판

### 3A. 점수 산정

13개 체크리스트 항목 각각에 대해:
- 건강 (YES) = 0점
- 위험 (NO) = 1점

총점 범위: 0-13

### 3B. 3단계 판정

| 점수 | 판정 | 조치 |
|---|---|---|
| 0-3 | **Safe** (건강) | 현행 유지. 분기별 재점검 |
| 4-7 | **Watch** (주의) | 해당 항목 개선 로드맵 수립. 6주 내 재점검 |
| 8-13 | **Restructure** (재설계 필요) | 제품 코어 루프 재설계 착수. 출시 중단 검토 |

### 3C. 필수 재설계 트리거 (점수와 무관)

다음 패턴이 하나라도 감지되면 점수와 무관하게 **즉시 재설계**:

**트리거 1 -- 자율성 역전**
AU-1(독립 실행 테스트)이 NO이고 동시에 GA-1(코호트 갭 축소)이 NO
→ 사용자가 더 무능해지면서 갭도 안 줄어드는 최악의 조합

**트리거 2 -- 인위적 갭 루프**
GA-4(닫힌 갭 재활용)가 NO이고 동시에 GA-3(재구매 동기)가 NO
→ 이미 해결된 문제를 반복 판매하면서 불안으로 유지

**트리거 3 -- 정체성 납치**
SA-1(제품 외 정체성 표현)이 NO이고 동시에 AU-4(데이터 이동성)가 NO
→ 사용자의 전문 정체성이 제품에 갇혀있고 탈출 불가

### 3D. Ethical_Coefficient 근사 산출

체크리스트 점수를 Ethical_Coefficient로 변환:

```
Ethical_Coefficient_proxy = (13 - 빠짐_점수) / 13

Safe (0-3):        EC ≈ 0.77 - 1.00
Watch (4-7):       EC ≈ 0.46 - 0.69
Restructure (8-13): EC ≈ 0.00 - 0.38
```

이 프록시를 D(WTP)_sustainable 공식에 대입하면 장기 WTP 잠재력 추정이 가능하다.

## 4. 건강한 고WTP 제품 설계 원칙 (5개)

### 원칙 1: 프론티어 확장 (Gap Escalator)

**이론적 근거**: Gap_Intensity는 Functional_Gap + Social_Position_Gap의 합이다. 건강한 제품은 기존 갭을 닫으면서 더 높은 수준의 갭을 공개한다. 사용자가 성장했기 때문에 보이는 새 갭이므로, 인위적 갭 재생산이 아니라 인식론적 프론티어 확장이다.

**설계 규칙**: 매 세션 종료 시 "닫힌 갭 1개 + 새로 발견된 갭 1개"를 명시적으로 보여줘라.

**Career Mirror 적용**: 사용자가 발산점 1개를 닫으면(자가 신고 진도 업데이트), 시스템이 자동으로 한 단계 위 아웃컴 티어에서 새 발산점을 계산한다. "축하합니다. 이 갭은 닫혔습니다. 그런데 당신이 목표하는 다음 단계에서는 이것이 보입니다."

**반례**: 듀오링고의 스트릭 시스템. 갭을 닫아도 새 프론티어가 아닌 "연속 기록 유지"가 리텐션 동기. 프론티어 확장 없는 습관 유지 = 빠짐 조건 4(자율성 인식 왜곡) 위험.

### 원칙 2: 졸업 설계 (Graduation Architecture)

**이론적 근거**: Ethical_Coefficient = 1.0은 "이상 상태 도달 가능"을 의미한다. 이상 상태에 도달한 사용자는 제품이 필요 없어져야 한다. 역설적으로, 졸업을 설계하면 D(WTP)_sustainable이 **증가**한다.

**왜 역설적 증가인가**: 졸업이 가능하다는 사실 자체가 제품의 신뢰성을 증명한다. "이 제품을 쓰면 결국 안 써도 되는 수준에 도달한다"는 메시지가 L4-L5 사용자의 구매 장벽을 제거한다. 반면, 졸업 불가능한 제품은 "영원히 돈을 내야 한다"는 불신을 형성하여 최초 전환율이 낮아진다.

**설계 규칙**: 명시적 졸업 조건을 제시하라. "이 5개 발산점이 모두 닫히면 당신은 이 티어를 졸업합니다."

**Career Mirror 적용**: 목표 아웃컴 대비 발산점이 모두 닫힌 사용자에게 "졸업 배지"를 발급하고, 해당 사용자의 익명화 궤적을 시드 코호트에 추가한다. 졸업생은 무료 전환 + "멘토 코호트" 역할 제안. 떠나도 되고 남아서 기여해도 되는 구조.

**반례**: 넷플릭스. 콘텐츠 소비에 졸업이 없다. 건강한 습관과 의존을 구분하기 어려운 구조. 이것이 넷플릭스의 D(WTP)_sustainable이 콘텐츠 비용 대비 낮은 이유 중 하나다.

### 원칙 3: 메타 투명성 (Meta-Transparency)

**이론적 근거**: v1 이론의 실천 원칙 3 "메타 레이어를 명시적으로 드러내라"의 확장. 제품이 어떻게 사용자의 갭을 보여주고 왜 이 방식이 효과적인지 **설명하면**, 사용자의 자율적 숙고 능력이 보존된다 (Noggle 자율성 기준 충족).

**설계 규칙**: "이 제품이 당신에게 효과적인 이유"를 제품 내에서 한 번 이상 설명하라. 작동 원리를 아는 사용자가 더 의도적으로, 더 오래, 더 많이 추천한다.

**Career Mirror 적용**: 갭 시각화 하단에 "이 분석이 작동하는 원리" 링크를 상시 제공. "당신의 궤적을 아웃컴 달성자 코호트와 비교하여 통계적 발산점을 찾습니다. 이 방법의 한계는..."까지 공개. 신뢰 구축이 L5 전환의 핵심 조건이므로 투명성은 전환율을 올린다.

**반례**: 점술/운세 앱. 작동 원리를 절대 설명하지 않는다. 불투명성이 "신비로움"으로 포장되지만, 이것이 Ethical_Coefficient를 0에 가깝게 만드는 핵심 원인이다.

### 원칙 4: 역설적 역량 이전 (Counter-Intuitive Capability Transfer)

> 이것이 반직관적 원칙이다: **사용자가 제품 없이도 할 수 있게 가르치면, 오히려 더 오래 머문다.**

**이론적 근거**: D(WTP)_sustainable = D(WTP)_instantaneous x Ethical_Coefficient에서, 역량 이전은 Ethical_Coefficient를 1.0에 가깝게 유지한다. 동시에 사용자의 Autonomy가 올라가면 **더 높은 수준의 Gap_Intensity가 인지 가능해진다** (이전에는 보이지 않던 L5급 갭이 보이기 시작). 결과적으로 Gap_Intensity가 올라가서 D(WTP)_instantaneous도 증가.

수학적으로:

```
역량 이전 없음:
  EC = 0.5 (의존 형성)
  Gap_Intensity = 초기 갭 유지 (성장 없음)
  D(WTP)_sust = G_0 x A x SA x 0.5

역량 이전 있음:
  EC = 0.95 (건강)
  Gap_Intensity = G_0 + delta_G (새 프론티어 인지)
  D(WTP)_sust = (G_0 + delta_G) x A x SA x 0.95
```

delta_G > 0이면 (프론티어 확장 작동 시), 역량 이전 있는 쪽이 D(WTP)_sustainable이 **더 높다**. 이것이 "건강한 제품이 더 높은 지속 WTP를 생성한다"는 비자명한 결론의 수학적 근거다.

**설계 규칙**: 매월 "이번 달 배운 것을 제품 없이 적용하는 법" 콘텐츠를 제공하라. 수익 감소처럼 보이지만, 실제로는 갱신율을 높인다.

**Career Mirror 적용**: 월간 이메일 "당신의 궤적이 업데이트되었습니다"에 "이번 달 닫은 갭을 스스로 모니터링하는 법"을 포함. 사용자가 제품 없이 자기 궤적을 추적하는 프레임워크를 제공하되, 제품이 제공하는 코호트 비교 데이터는 독립적으로 재현 불가능하므로 자연스러운 차별화 유지.

**반례**: 대부분의 SaaS 분석 도구. 사용자에게 분석 방법론을 가르치지 않고 대시보드만 제공. 사용자는 대시보드 없이 의사결정을 못 하게 됨. 높은 리텐션이지만 낮은 EC → 대체제 등장 시 급속 이탈.

### 원칙 5: 사회적 기여 경로 (Social Contribution Path)

**이론적 근거**: Social_Amplifier는 "기능적 갭이 중요한 타인에게 보이는 정도"다 (v2 재정의). 건강한 제품은 사용자가 **받는** 사회적 신호뿐 아니라 **주는** 사회적 기여를 설계한다. 기여자 정체성은 소비자 정체성보다 강하고 지속적이다.

**설계 규칙**: 사용 6개월 이상 사용자에게 "기여자 역할"을 제안하라. 기여자는 자신의 성장을 확인하는 동시에 커뮤니티의 Social_Amplifier를 높인다.

**Career Mirror 적용**: 졸업한 사용자가 익명 궤적 데이터를 시드 코호트에 기부하면 피어 코호트 매칭에서 우선 연결. "당신의 데이터가 3명의 후배에게 발산점을 보여줬습니다"라는 피드백. 기여가 정체성을 강화하는 건강한 루프.

**반례**: 링크드인 Premium. 사용자가 기여할 수 있는 경로가 제한적. "받는 것"(누가 프로필을 봤는지)에 집중. 소비 중심 Social_Amplifier는 빠짐 위험이 높다.

## 5. Career Mirror 빠짐 감사 적용

### 5A. 사전 감사: MVP 설계 리스크 진단

Career Mirror MVP (iter 5)의 핵심 기능별 빠짐 위험 평가.

**기능: 커리어 타임라인 5필드 입력 (Step 1 Input)**
- 빠짐 위험: **낮음**
- 이유: 입력은 일회성이고, 사용자가 자기 데이터를 생성하는 행위 자체가 자율성 향상

**기능: 목표 코호트 비교 궤적 시각화 + 발산점 3개 공개 (Step 2 Reveal)**
- 빠짐 위험: **중간**
- 위험 요소: 발산점이 매번 "부족한 것"만 보여주면 하향 비교 유도 (SA-2 위반 위험)
- 완화책: 발산점 표시 시 "당신이 코호트보다 앞선 지점"도 함께 표시. 결핍만이 아닌 강점 동시 공개

**기능: "이 갭을 닫는 경로를 보시겠습니까?" CTA (Step 3 Action)**
- 빠짐 위험: **낮음-중간**
- 위험 요소: CTA가 즉시 결제를 유도하면 AU-2(숙고 시간 보존) 위반
- 완화책: CTA 클릭 → 상세 프리뷰(블러 해제 일부) → 24시간 후 결제 리마인더. 즉시 결제도 가능하되 기본 경로는 숙고 유도

**기능: Free→Paid 블러 처리 (발산점 라벨은 공개, 상세는 유료)**
- 빠짐 위험: **낮음**
- 이유: 라벨 자체로 사용자가 독립적으로 갭을 인지하고 행동할 수 있음. 상세는 "편의 가속"이지 "유일한 경로"가 아님

**기능: 월간 재분석 (커리어 데이터 업데이트 시)**
- 빠짐 위험: **중간**
- 위험 요소: 매월 새 발산점을 보여주면서 "갭 재생산"처럼 작동할 가능성 (GA-4 위험)
- 완화책: 닫힌 갭을 명시적으로 "닫힘" 표시. 새 발산점은 반드시 상위 티어에서만 생성. 같은 수준의 갭 재활용 금지

**기능: 피어 코호트 매칭 (같은 경로에서 12개월 앞선 사람 연결)**
- 빠짐 위험: **낮음**
- 이유: 실제 사람과의 연결은 제품 밖에서도 유지 가능. 제품이 연결을 독점하지 않음

**기능: 공유 잠금 해제 메커니즘**
- 빠짐 위험: **낮음**
- 이유: 공유 행위 자체가 사용자의 자율적 선택. 공유 없이도 유료 전환 가능

**기능: Anti-빠짐 설계 (닫힌 갭 → 재계산 → 프론티어 확장)**
- 빠짐 위험: **최저**
- 이유: 이것은 빠짐 방지 메커니즘 자체. 올바르게 구현되면 GA-1, GA-4, GA-5 모두 충족

### 6C. 패턴 분석

## 7. 빠짐 -> 건강 전환 패턴

### 7A. 전환 패턴 1: 갭 에스컬레이터 삽입

**문제**: 제품이 동일 수준의 갭을 반복 생성 (GA-4 위반)
**해법**: 닫힌 갭 추적 시스템 + 상위 레벨 갭 자동 생성

**사례: 가상 온라인 코딩 교육 플랫폼**

Before:
- 초급 파이썬 과정 완료 → "파이썬 중급도 들어보세요" → 내용 80% 중복
- 리텐션 높지만 학생 실력 정체, 이탈 시 만족도 낮음
- 갱신 동기: "아직 배울 게 남은 것 같아서" (불안)

After:
- 초급 완료 → "초급 졸업 테스트" 통과 → 졸업 표시
- 졸업 후 "당신이 이제 볼 수 있는 새 프론티어" 자동 공개: 오픈소스 기여, 시스템 설계 등 이전에 인지 불가했던 갭
- 같은 레벨 콘텐츠 재추천 차단

예상 변화:
- 단기 리텐션: 하락 (졸업 이탈 허용)
- 장기 LTV: 상승 (상위 과정 전환율 증가 + 추천율 증가)
- 갱신 동기: "새로운 것을 배우고 싶어서"로 전환
- 빠짐 점수: 7 → 2

### 7B. 전환 패턴 2: 투명성 삽입

**문제**: 제품 작동 원리가 불투명 (AU-3 위반) + 대안 차단 (조건 2)
**해법**: 메타 투명성 레이어 추가

**사례: 가상 커리어 컨설팅 구독 서비스**

Before:
- 월 구독료 → AI가 이력서 피드백 제공
- 작동 원리 미공개. "우리 AI가 분석했습니다"만 표시
- 사용자는 AI 없이 이력서를 개선할 수 없다고 느낌
- 대안(무료 이력서 가이드, 동료 피드백) 미안내

After:
- "이 피드백이 생성된 원리" 설명 추가: "채용 담당자 500명의 선호 패턴 데이터 기반"
- "AI 없이 이력서를 개선하는 3가지 방법" 가이드 상시 제공
- 사용자가 직접 체크리스트로 자가 검토할 수 있는 프레임워크 제공

예상 변화:
- 이탈률: 초기 소폭 상승 (자가 검토로 충분한 사용자 졸업)
- 잔존 사용자 만족도: 대폭 상승 (신뢰 증가)
- 추천율: 상승 ("여기서 방법을 배웠다" vs "여기 없으면 안 된다")
- 빠짐 점수: 8 → 3

### 7C. 전환 패턴 3: 기여자 경로 삽입

**문제**: 사회적 기능이 소비 중심 (SA-1 위반) + 정체성 대체 위험
**해법**: 기여자 역할 경로 추가

**사례: 가상 전문가 커뮤니티 플랫폼**

Before:
- 사용자는 콘텐츠 소비자 + 프로필 관리자
- 플랫폼 내 정체성이 "이 플랫폼의 활발한 사용자"
- 플랫폼 밖에서 전문성 표현 시 "그 플랫폼 보세요" 의존
- 떠나면 전문 네트워크 + 콘텐츠 접근 동시 상실

After:
- 6개월 이상 사용자에게 "멘토/기여자" 역할 제안
- 기여자는 자기 전문 지식을 플랫폼 내 가이드로 작성
- 가이드 작성 과정 자체가 전문성 정리 → 플랫폼 밖에서도 활용 가능한 자산 생성
- "당신의 가이드가 47명에게 도움이 됐습니다" = 기여자 정체성 강화
- 프로필 + 가이드 + 네트워크 완전 내보내기 지원

예상 변화:
- 기여자 전환 사용자의 LTV: 비기여자 대비 2-3배 [추정]
- 플랫폼 외 정체성 표현: "그 분야의 전문가"로 전환
- 이탈 후 만족도: 대폭 상승 (자산이 남으므로)
- 빠짐 점수: 9 → 3

### 7D. 전환 패턴 공통 원리

세 패턴 모두에서 관찰되는 구조:

1. **단기 지표 악화를 수용한다**: 리텐션, 접속 빈도가 일시적으로 하락할 수 있다. 이것이 "빠짐 해제"의 자연스러운 증상이다.
2. **장기 지표가 보상한다**: LTV, 추천율, 갱신 동기 품질이 향상된다.
3. **Ethical_Coefficient 상승이 D(WTP)_sustainable을 끌어올린다**: 공식이 예측하는 대로, EC가 0.5→0.9로 오르면 instantaneous WTP가 다소 낮아져도 sustainable WTP는 순증가한다.

이것이 빠짐 감사 프레임워크의 핵심 통찰이다: **빠짐을 제거하면 단기 수익이 줄어든다는 공포는 수학적으로 거짓이다.** Ethical_Coefficient 향상에 의한 sustainable WTP 증가가 instantaneous WTP 감소를 능가한다 -- 프론티어 확장이 작동하는 한.

## 부록 A: 빠짐 감사 실행 가이드

### 감사 주기

- **사전 감사**: 제품 출시 전 설계 단계에서 1회 (Section 5A 방식)
- **출시 후 감사**: 분기 1회 (13개 체크리스트 전체 + 점수 산정)
- **긴급 감사**: 다음 신호 중 하나라도 감지 시 즉시 실시
  - 갱신 서베이에서 "불안" 동기가 30% 돌파
  - 이탈 후 만족도가 전분기 대비 20% 이상 하락
  - 필수 재설계 트리거 3개 중 하나 충족

### 감사 팀 구성

- 제품 매니저 (체크리스트 진행)
- 데이터 분석가 (정량 지표 측정)
- 사용자 연구원 (정성 인터뷰 -- GA-3, AU-1, SA-1)
- 윤리 자문 (외부, 분기 1회) -- 내부 편향 방지

### 산출물

- 13개 항목 점수표
- 판정 (Safe/Watch/Restructure)
- 필수 재설계 트리거 해당 여부
- (Watch/Restructure인 경우) 개선 로드맵 + 6주 후 재감사 일정

## 부록 B: 이론적 기반 요약

본 프레임워크는 다음 이론적 토대 위에 구축되었다:

- **VALUE GAP Theory v2** (본 연구): D(WTP)_sustainable = D(WTP)_instantaneous x Ethical_Coefficient
- **Fogg B=MAP 모델**: 행동 = 동기 x 능력 x 촉발자. 빠짐은 촉발자를 과도하게 설계하여 숙고 없는 행동을 유발할 때 발생
- **Noggle(1996) 자율성 보존**: 조작의 핵심 조건 = 숙고 능력 침해 또는 이해관계 불일치
- **Deci & Ryan SDT**: 자율성, 유능감, 관계성 기본 욕구. 빠짐 제품은 자율성을 침해하면서 유능감 환상을 제공
- **Prospect Theory (Kahneman & Tversky 1979)**: 참조점 재정의에 의한 갭 인지 조작 가능성 → 인위적 갭 제조의 메커니즘
